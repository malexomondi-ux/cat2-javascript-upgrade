IMPLEMENTATION NOTES
Hayley Kakanga Restaurant — CAT 2 JavaScript Upgrade


1. LOOP-RENDERED DYNAMIC CONTENT
   Location: script.js (top section) / index.html #testimonials section

   A "testimonials" array holds three customer review objects, each with a
   "name" and "comment" property. A forEach() loop reads each object,
   builds a <div class="testimonial-card"> using createElement(), fills
   it with the customer's name and comment via textContent, and appends
   it into the empty #testimonialList container with appendChild(). None
   of the testimonial cards exist in the HTML directly — they are all
   generated by JavaScript when the page loads.

2. DYNAMICALLY ADD & REMOVE ELEMENTS
   Location: script.js / index.html #testimonials section (review form)

   Visitors can add their own review using the "Leave Your Own Review"
   form (#reviewName, #reviewComment, #addReviewBtn). Clicking "Add
   Review" reads the input values, checks that neither is empty, then
   uses createElement() and appendChild() to build a new testimonial
   card with the same structure as the loop-rendered ones, plus a
   "Delete" button. Each delete button has its own click listener that
   calls card.remove(), removing only that specific card from the page.

3. FORM HANDLING WITH VALIDATION FEEDBACK
   Location: script.js / index.html #reservation section

   The reservation form (#reservationForm) uses event.preventDefault()
   on submit to stop the page from reloading. JavaScript reads all four
   field values with .value and checks that the name is not empty, the
   date is not empty, and the number of guests is a valid number greater
   than 0. Any problems found are collected into an array and displayed
   as a bulleted list inside #reservationFeedback using innerHTML,
   styled in red via the error-text class. If all fields pass
   validation, a green confirmation summary (success-text class) is
   shown using the actual submitted values, and the form is cleared with
   reservationForm.reset().

4. PERSISTENT STATE WITH LOCALSTORAGE
   Location: script.js (bottom section) / #testimonials section

   Visitor-added reviews are saved so they survive a page reload. A
   MutationObserver watches the #testimonialList container for any
   change — a card being added or removed. Whenever that happens, all
   current cards are re-read from the DOM, the three original hardcoded
   testimonials are filtered out (by comparing against the testimonials
   array), and the remaining visitor-added reviews are saved to
   localStorage as a JSON string using JSON.stringify(). On page load,
   any saved reviews are read back with JSON.parse() and re-added to the
   page by programmatically filling the review form and triggering the
   same "Add Review" logic used for manual entries.

5. CLICK-TO-REVEAL ON BANNER
   Location: script.js / index.html .hero section

   The banner image (#bannerImage) has a click event listener attached.
   Each click calls classList.toggle("show-caption") on the hidden
   caption box (#bannerCaption), which contains the chef's name and a
   short bio. The CSS hides .banner-caption by default (display: none)
   and reveals it (display: block) when the show-caption class is
   present, so each click alternately shows and hides the overlay.
